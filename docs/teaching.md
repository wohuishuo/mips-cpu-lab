# 从一条指令到真实电路

可以按六个问题讲解这个项目。每个问题都对应一段能实际运行的程序或测试，
让报告从“我写了哪些模块”推进到“这个硬件怎样正确执行程序”。

## 1. CPU到底在重复做什么？

PC给出指令地址，ROM返回32位指令。译码电路选择源寄存器、运算和目标寄存器，
ALU产生运算结果或访存地址，最后在时钟边沿写回状态。下一拍重复这个过程。
例如`addiu $t0,$zero,1`把立即数符号扩展，与恒为零的寄存器相加，写入$t0。
它不需要数据RAM，但仍然占用单周期CPU的一整个时钟周期。

`lw`的路径更长：取指、译码、地址相加、RAM读取、寄存器写回都要及时完成。
因此“每条指令一个周期”不等于“处理器一定很快”。本板级单周期设计选择10MHz，
是否能运行取决于布局布线后的时序报告，而不是仿真时间单位写成多少纳秒。
可对照课件07第2–5页和`single_cycle_cpu.v`。

## 2. 为什么汇编正确还不足以证明CPU正确？

我们先让MARS实际汇编并运行Fibonacci，得到12个期望值；再把同一份机器码
装入RTL的ROM，检查真实存储地址、字节写使能和每一个结果。若只看最后一个
寄存器，CPU把结果写到错误的RAM地址也可能漏过。因此审查后增加了完整地址
窗口和严格存储顺序检查，且用错误地址变异确认测试会失败。

数列从0、1开始，后项由相邻两项相加得到。最后三项为34、55、89。
板级程序将最后的89重新从RAM加载，再写入显示寄存器，数码管以十六进制显示59。
UART遥测中的最后结果来自观察到的第12次RAM存储；显示值则经过真实的CPU加载。

## 3. 分支为什么需要专门讲延迟槽？

这里采用一个显式MIPS分支延迟槽。分支后的那条指令执行一次，然后才切换到目标。
板级Fibonacci把指针加4安排在`bne`后面；最后一次分支不跳转时，指针同样前进。
随后`lw $s2,-4($s0)`才能取到刚写入的最后一项。

`jal`保存的是PC+8，因为PC+4对应延迟槽。MARS的延迟分支选项和CPU必须一致。
本实现对延迟槽里的再次控制转移作确定的非法指令处理，不能宣称支持所有
MIPS架构中本就不可预测的组合。相关行为有独立PC和写回值测试。

## 4. 五级流水线怎样保持正确？

IF、ID、EX、MEM、WB同时处理不同指令。每级保留自己的有效位、PC和指令，
有效位为零表示气泡。流水线提升的是连续指令吞吐，单条指令仍需穿过多个阶段。

相邻指令可能依赖尚未写回的结果。本实现优先把MEM较新的结果前推到EX，
其次使用WB结果；源寄存器为零时始终得到零。load-use需要等待，因为加载数据
在更晚阶段才可用。等待外部存储时，年轻级保持，WB排空一次，不能每个等待拍
都重复退休或重复写寄存器。存储也只能在一次有效握手边沿发生。

演示时可选取`pipeline_stages.csv`里的一段，逐拍标注同一条PC经过哪个阶段。
停顿、气泡和错误冲刷都能从阶段有效位看出。课件10第6–8页解释流水寄存器，
第13–22页提供冒险背景；本项目的信号名与图中的标注保持一致。

## 5. 异常如何做到“精确”？

发生异常的指令不提交错误结果，它之前的指令允许完成，之后的指令不能留下
寄存器或存储副作用。CP0保存Cause、Status、EPC及必要的BadVAddr。延迟槽异常
设置BD，并把EPC指向所属分支。ERET清除异常级别并返回EPC。

单周期参考核的ADD/ADDI/SUB采用明确记录的环绕行为；流水线版本对有符号溢出
产生异常。两者做差分时必须避开这个有意的语义差异，或让参考模型也建模异常。
流水线的中断在安全的非延迟槽EX边界接收，先完成较老的MEM事务，避免返回后
重新执行一条已经对外生效的存储。测试专门让中断与等待中的老存储相遇。

CP0定时器审查还发现一个边界：软件把Count从99写成0、Compare为100时，
不能使用旧Count+1误报匹配。比较器必须看真正提交的下一Count值。
这说明普通“计时到12”的通过用例还不够，边界和反例同样是设计的一部分。

## 6. Cache和外设为什么要分别处理？

普通RAM可以缓存。两路组相联Cache把地址分成Tag、组号、行内偏移；未命中时
选择一路替换，脏行先写回，随后回填目标行。部分字节写入必须合并正确字节，
等待中的请求必须保持地址、数据和写使能稳定。

外设寄存器有可观察副作用。LED或蜂鸣器的写入不能等到Cache替换时才到达外设，
所以MMIO绕过Cache。UART使用8N1串行协议；在示波图或独立串行采样中检查起始位、
数据顺序、停止位，比把同一套TX/RX互接后只看一个“通过”更有说服力。

汇报收尾时回到证据：哪些结果来自软件参考，哪些来自RTL仿真，哪些来自真实串口，
哪些只是帮助理解的动画。再给出资源、时序、CPI与明确未实现的范围，读者就能
复现和评价这个设计，而不必相信一张孤立的“运行成功”截图。
